## Implementation details
1. **Config (`public/src/config.js`)**:
   - Added `CONFIG.tutorial.stepMaxMs = 12000` (max duration per step before auto-advancing).
   - Added `CONFIG.tutorial.maxMs = 45000` (global max duration before the entire tutorial completes).
2. **Engine (`public/src/engine.js`)**:
   - In `setupTutorialJump`: spawned barrier items across all 3 lanes at the barrier's `z` (`bZ`), making jumping or hitting the only way through.
   - In `setupTutorialLanes`, `setupTutorialChain`, and `setupTutorialJump`: tracked `state.tutorial.lastItemZ` and supported `isNewStep` parameter to preserve `stepTimerMs` when respawning after a miss/hit.
   - In `tick`:
     - Once the runner is more than 6 m past a step's `lastItemZ` without completing it, that step's pattern is respawned ahead (items appear ahead within ~1.6 s, well under the 2 s limit).
     - Each step auto-advances if `stepTimerMs >= stepMaxMs` (12 s), emitting the required `{ type: 'tutorial', step }` event and setting up the next step.
     - Hard global limit: if `state.tutorial.totalMs >= maxMs` (45 s), `finishTutorial` terminates the tutorial immediately, resetting `chaserStep = 0`, emitting `tutorial done`, and handing over to normal track generation.
3. **Tests (`tests/tutorial.test.mjs`)**:
   - Added full-width barrier check preventing lane dodging in `jump` step.
   - Added idle runner test ensuring `done` is reached in $\le 45$ s without ever being caught.
   - Added seeded random key-mashing test ensuring `done` is reached in $\le 45$ s.
   - Added chain pattern miss respawn test verifying new items appear ahead within 2 s.
   - Verified all existing scripted tutorial and post-tutorial tests continue to pass.
