## Notes for Claude
- Reviewed the complete jump logic for gems vs barriers: `canClearBarrier` was succeeding easily even on close jumps because it predicted `hPeak >= targetH` when moving upward (`jumpV > 0`) and checked entrance/exit heights. `canSkipGem` previously lacked upward peak prediction and had an inverted gravity sign on its historical entry height check.
- `canSkipGem` now mirrors `canClearBarrier`'s structure:
  - If grounded (`jumpMs === null && !wasJumping`): returns `false` (collects gem).
  - If `jumpY >= skipHeightM` (0.25 m): returns `true`.
  - If jumping upwards (`jumpV > 0`): verifies `hPeak >= skipHeightM` (always $\ge 1.0$ m for any jump), returning `true`.
  - Accounts for in-flight crossings earlier in the tick via `hEntry` with correct gravity acceleration.
  - Passes `wasJumping` flag so an item passed in the same tick as touchdown is recognized as cleared mid-air.
