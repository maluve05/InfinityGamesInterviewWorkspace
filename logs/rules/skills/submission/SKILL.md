# Submission

Follow, in order:

1. `scale-or-kill` — settle the verdict and its reasons first; the video and the
   answers both depend on it.
2. `processes/recording.md` — the ~3-minute walkthrough (owner records): the
   prototype running, which top-chart game inspired it, scale or kill and why.
3. `processes/prompt-log.md` — `npm run logs` (Claude sessions, worker
   transcripts, rules files); commit `logs/` so one GitHub link opens everything.
   Spot-check one file per tool.
4. `REFLECTION.md` — answer the email's exact questions. Be specific: tools,
   times, what the AI got wrong and how it was fixed, what the owner changed by
   hand, what broke. No marketing language, no invented numbers — quote real test
   counts and timings from actual output.
5. `processes/submission.md` — pre-send checklist and email template. Links, not
   heavy attachments; everything opens without an account.

The assessors value honesty over polish. If something failed, say what, when,
and what you'd do next. Send what works, before the deadline.
